# CareerCrew 产品完善与新增功能路线图

更新时间：2026-09-11（第一至第五期已交付；第七、八期完成代码、自动化与本地 live 验收，生产发布门禁待对应环境执行）。

## 目标与实施约定

围绕一个目标岗位贯通 JD、岗位专属简历、模拟面试与后续跟进。用户已确认：先完整交付第一期，再按计划推进第二、三期。第四期起重心从「增加独立功能」转向「让所有数据真正围绕一个岗位形成完整档案」。第一期至第三期执行细节见 [实施计划](superpowers/plans/2026-09-06-job-preparation-phase1.md)，浏览器验收见 [验收报告](superpowers/plans/2026-09-06-job-preparation-verification.md)。

当前基础：React / FastAPI 对话、岗位检索、简历上传解析、逐题面试、长期记忆、质检与评测。已有能力延伸为产品流程，不重复建设 Agent。

## 第一期：完成一次岗位准备（✅ 已交付）

1. **岗位卡片**：从成功检索的结构化结果渲染公司、岗位、城市、薪资、来源、JD；卡片随对话持久化，旧记录没有结构化数据时仍显示原回答。
2. **手动录入与收藏**：独立“岗位准备”入口；填写公司、岗位、JD、来源链接；必填校验、编辑、搜索、删除；刷新不丢失、账号隔离。第一期手动入口采用粘贴文本，截图解析继续使用已有附件能力，自动从链接抓取不在本期范围。
3. **岗位关联**：每个收藏保存 JD 快照；同一岗位下关联简历版本和准备会话，来源链接仅允许 HTTP/HTTPS。收藏不会自动投递或联系 HR。
4. **简历版本与编辑**：从现有简历库选取原文，也可粘贴原文；手动编辑、原文/当前稿对照、保存不可变版本、查看历史版本。简历顾问的完整回答可由用户显式载入编辑器，确认后保存，避免将解释文字直接当正式简历。
5. **导出**：指定已保存版本导出真正的 PDF 和 DOCX；中文可读、换页不丢字、名称安全。保留原始上传简历，不覆盖。
6. **针对岗位的模拟面试**：从岗位及选定版本创建准备会话，进入现有面试模块；清楚展示使用的岗位和简历版本；首次输入预填，用户点击开始后才调用 AI；后续轮次及历史会话继续使用关联上下文。

### 第一期验收场景

- 用户手动录入“测试公司 / Java 开发 / JD”，刷新后仍能找到；另一个账号不能读取、编辑、导出或关联这条数据。
- 用户在匹配结果收藏岗位，不需要重新粘贴 JD；重新打开有结构化结果的历史对话仍能看到卡片。
- 在该岗位下选择已有简历、编辑并保存两个版本，旧版本保持不变；分别下载 PDF/DOCX，与选定版本一致。
- 从指定版本进入简历优化或面试，自动带入同一份 JD 与简历；切到其他会话不带错上下文；刷新后历史关联能恢复。
- 无 JD、空简历、超长输入、危险链接、重复点击、接口失败均给出可理解反馈；保存失败保留编辑内容。
