# Phase 8 工作台与协作增强验收

更新时间：2026-09-10

## 交付范围

第八期完成了四个 P1/P2 工作台切片，并保持个人账号边界：

- 追溯与行动：跨会话全文回退搜索、书签、消息边界分支、来源关联行动项。
- 可解释会诊：共识、分歧、替代方案、证据、风险、报告确认和执行计划确认/撤回。
- 简历母版：母版/派生版本、差异对比、经历素材、批注、异步 PDF/DOCX 批量导出和有限轮询。
- 工具中心：工具状态、MCP 受限说明、有效权限、脱敏调用记录、失败分类、管理员策略和审计。

语义向量索引尚未强行替换现有链路：搜索 API 会明确返回 text_fallback，等向量索引基础设施可用后再接入真正的跨会话 embedding 检索。

## 数据与安全边界

- 0012–0015 建立工作台关系表；0016 增加消息、会话、报告、简历版本等跨表 owner 组合外键。
- 每个读写 API 都先按当前账号查询资源；ID 不是授权凭据。
- 报告/计划、简历导出、工具启停都是独立用户动作，不会因生成草案自动执行。
- MCP 不在浏览器探测，也不把凭据或 raw arguments 返回给用户。

## 浏览器与 live 数据库验收

本机本轮未完成真实浏览器验收：:8000、:5175、:5432 当前没有监听服务，且认证服务只支持 PostgreSQL-backed 登录。待服务启动后必须用真实账号补验：

1. /workspace 四个 tab 的数据加载、错误提示和刷新。
2. 375px 与桌面宽度下 tab、表单、按钮和下载动作。
3. 普通用户看不到工具启停按钮，管理员可启停并在审计中看到记录。
4. 两个账号互相不能读取书签、行动项、会诊报告、简历版本或工具调用历史。
5. 导出任务从 queued/running 到 done/failed 的轮询及过期下载。

## 组织协作规模决策

当前产品仍以单用户/管理员/质检员为主，尚无已验证的多人组织使用量。因此本期不引入组织、导师、成员、知识库审核和细粒度组织审计；继续保留 owner-scoped 结构，为未来通过 tenant_id/org_id 和 RLS/组合外键扩展留出边界。出现稳定的多人协作需求后再立项，避免现在扩大权限面。

## 发布判定

Phase 8 功能实现和自动化验证已完成，浏览器、真实数据库迁移、Qdrant/导出 worker 运行态验收仍是部署环境门禁；本地未将这些阻塞项误报为通过。
