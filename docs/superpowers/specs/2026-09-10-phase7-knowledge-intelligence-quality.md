# CareerCrew 第七期：知识与智能质量闭环规格

## 目标

把现有的“能调用、能检索、能记录”提升为可回归、可纠错、可计量的质量闭环。第一版必须保持用户确认边界：模型只生成草案，用户决定确认、保存、执行；所有人工治理动作都留下可回溯记录。

## 范围

本期覆盖以下 P1 能力：

1. 真实模型评测：固定脱敏测试集、实际模型调用、模型/Prompt/数据集可追溯对比，以及可阻断发布的回归门禁。
2. 长期记忆治理：确认、修改、暂时忽略、标记过期、冲突合并、历史与乐观锁。
3. 知识库治理：文档逻辑身份、版本、SHA-256 去重、分块预览、整版重索引、失效日期、来源可信度、引用命中统计。
4. 成本与观测：用户/模块用量与费用估算、日/月预算、可审计降级，以及 Prometheus 基础指标。

跨会话对话搜索、消息分支、会诊决策报告、简历母版和工具中心属于第八期；本期只保留接口边界，避免把会话、知识和 Career Crew 第五月度脏改动混为一次提交。组织协作暂缓，直到出现真实的多人租户需求。

## 非目标

- 不自动投递简历、联系 HR、执行外部行动或把 AI 建议当作用户确认。
- 不修改已发布的 `0008_prod_hardening`；所有新结构从 `0009` 起新增迁移。
- 不把 JD、简历、Prompt、模型输出、API key、原始工具参数或附件正文写入费用表、Prometheus label 或通用审计日志。
- 不以“缺少密钥/服务”伪装成评测通过；可选观测和阻断门禁必须有不同退出语义。

## 质量与安全约束

### 评测

评测 case 使用稳定的 `case_id`、`dataset_id`、`target_agent`、`input`、`expected`、`rubric` 和 `severity`。每次实验保存代码 SHA、模型标识、Prompt 版本/hash、数据集版本、检索快照标识、temperature、运行 ID、时延、Token、错误类别和结构化输出校验结果。默认 temperature 为 0；比较报告同时给出均值、最差 case 和失败 case。

`--real` 只负责真实采集；`--require-real` 是发布门禁，缺配置、缺依赖、模型错误或任一关键 case 失败都返回非零；`--allow-skip` 只能显式用于 nightly 观测。固定离线门禁继续运行，真实基线只能由人工审核后更新。

### 记忆

所有读写先按当前用户过滤。`confirm/edit/ignore/expire/merge` 均记录 actor、理由、前后快照和 `row_version`。默认检索排除 ignored、expired、superseded、deleted；历史查询可看全部版本但不能越权。并发版本不匹配返回 409；合并仅允许同一用户、同一记忆类型且目标仍可治理。

### 知识库

每个逻辑文档有稳定 ID 和版本链；raw file hash 仅在同一 owner 范围内做重复判断，不向其他用户泄露存在性。版本索引采用“新版本完成后原子切换”；重索引失败不能破坏当前 active 版本。检索必须过滤 owner/public、active、未过期版本。引用统计使用脱敏的文档/版本/chunk ID 和计数，不保存回答正文。

### 成本与观测

账本事件不可变；未知价格必须显式标注不可估价，不能默认为 0。预算检查需保守预留，防止并发穿透；降级原因区分 provider failover、budget downgrade 和 deterministic fallback。Prometheus 只使用低基数枚举 label，避免用户 ID、资源 ID、正文和密钥。

## 验收结果

- 固定数据集离线评测和真实评测命令都有单元覆盖，阻断模式在失败时返回非零。
- 跨用户的记忆、文档、版本、分块、费用和计划 ID 均不可读取或修改。
- 记忆纠错产生可读历史；知识新旧版本和重索引状态可解释；过期内容不参与回答。
- 预算在边界和并发下不穿透，费用汇总与事件账本一致。
- `/metrics` 可被 Prometheus 抓取，且不泄露敏感业务内容。
- 后端/前端现有回归继续通过；与第五月度脏改动重叠的文件不得被无意覆盖。
